## 2c. Open work — verification card (branch `wip/verification-card`, not released)
**The problem (present in every version up to and including 1.1.11).** The recording runs on while the belt is stopped for the sample, but "last 5 min" HR/α1, the 10→30-min HR drift, run time, the SmO2 end slope and the end-sample rule are anchored to the end of the *recording*. One to three minutes of recovery pull HR down and SmO2 up and push the end-only MLSS proxy toward "at/below"; the "존에 반영" button then uses that heart rate. Synthetic example: a 100-s tail turns drift +8 into −0.8 and a falling SmO2 into "steady". **Until fixed: press 종료 right after typing the lactate value, walk afterwards, and do not trust the card's HR / drift / the HR part of "존에 반영" for a run that kept recording more than about a minute after the stop. Lactate values and the speed part are unaffected. The figures for the 10/4 and 10/5 runs in §3 were produced this way.**
**State of the rework.** Branch `wip/verification-card` (one commit on top of v1.1.10; it predates the last Bluetooth changes of v1.1.11, so rebase it onto main first) estimates the end of the run from heart rate (`exerciseEnd`), uses the phase log for LT2 sessions (`workBout`), makes the windows pause-aware, gives interval sessions their own verdict, and has a large synthetic test (`test/test_exercise_end.mjs`, `test/calib_exercise_end.mjs`). Two independent reviews said **not ready**:
1. Walk / jog 12–30 bpm below the run after the sample, Finish pressed while moving → estimate late (30–165 s inside the tail) or missing, and the card can offer a wrong zone change (e.g. "LT1 148→132 bpm", right would be 141). The planned LT1 checks sit in this band.
2. End not found (e.g. strap taken off before Finish): the drift figure ignored the recovery but the zone button did not → right verdict, wrong heart rate.
3. A Pause that is never released made the analysis discard the run.
4. Pace changes inside a drift window were taken for a belt stop (verdict flips); α1 for 2 min after a pause still contains pause beats; stage rows with a pause are only partly fixed.
5. LT2 mode: belt stopped before the rep clock without pressing anything; rest 0 between reps; session ended in the warm-up; interval session with purpose "LT1 check" still offered a zone change.
6. A value in the wrong slot of the card cannot be removed (emptying the field refills it from the event).
**Agreed direction for the next attempt:** (a) anchor the end of the run on the moment the end lactate value is saved (the stop is the last drop before it; classify each sample by whether the running resumed after it); (b) keep the heart-rate-only estimate as a fallback and never go on to later candidates with the old level; (c) whenever the end is uncertain (no anchor and the recording ends in a drop or well below the run) show a warning and offer no heart-rate-based zone change and no proxy verdict; (d) count a pause in the analysis only when the heart rate confirms the stop; (e) detect mid-run stops as dip-and-return episodes instead of by the distribution in a window; (f) once the card fields are edited, use exactly what they show; (g) validate on a real recording (export the 10/4 or 10/5 session) before release. Not done there either: the `keepAwake` same-tick corner (two opposite calls in one task when the first needs no change — not reachable from today's call sites).
- **Bluetooth — left from the focused review of v1.1.11 (all low; reasoned or shown on a simulated strap, none seen on a device):** (1) the 20-s limit covers link-up and service discovery together: a link that comes up late in an attempt is reset once and comes back on the next attempt (normally 1–5 s later; a strap that needed ~20 s to link every time would never get through — give discovery its own limit once the link is up), and a first connection slower than 20 s now fails with TimeoutError where v1.1.10 kept waiting; (2) between timed-out attempts the status reads "connecting", and Connect is not disabled while a first connection is in flight (further taps are ignored); (3) a link can stay open without an owner only if two pending `gatt.connect()` calls on one device settle differently, which Chromium does not do; (4) switching the sensor kind and picking the same strap again within 1.5 s relies on Chromium running stop/start of notifications in order.
- **Also proposed, not done (ask the owner):** (1) a switch to turn α1 guidance off for this athlete (LT1-mode voice "알파1 낮음", the −3 bpm auto-adjust and the α1 sub-labels all assume α1 0.75 = LT1, which §3 says is wrong here); (2) store SmO2 at 1 Hz in sessions (Train.Red exports are 10 Hz → ~1 MB per session, and Home/Plan load every session); (3) "finish" an unfinished autosaved session; (4) artifact voice warning in test/free modes; (5) a field in the verification card to set the end of the run by hand.

## 4. Solo protocol rules / 혼자 할 때 규칙
- Lactate technique: hands warm, washed with warm water and **fully dry (no alcohol residue, no sweat)**, wipe the first drop, no milking, fill the strip in one touch; end sample within 45 s of stopping; duplicate (two fingers) when a value looks odd (agree within 0.3). Keep caffeine/breakfast consistent on verification days. Strips: insert only when ready (2-min auto-off); meter ≥ 15 °C.
- **LT1 verification:** Free mode, speed entered, 35 min constant, cue "35". End ≤ 2.0 (and ≤ rest +1.0) → below; 2.1–2.5 → borderline; > 2.5 (or rise > 1.5) → above.
- **MLSS verification:** Free mode, **purpose = MLSS**, 30 min constant, warm-up outside the session, cue "30" (or "10,30" if a mid-run stop is possible: pause the app during the draw). **Press 종료 as soon as the end value is typed** — every minute of recording after the stop biases the card's heart rate and drift low (§2c). With a 10-min sample: rise ≤ 1.0 → at/below (next +0.3), > 1.0 → above (−0.4). End-only proxy: < 25 min → withheld; end < 3 → below; ≥ 6 → above; 3–6 with HR drift (min 8–13 → last 5) ≤ 6 bpm and SmO2 steady → likely at/below (+0.3); drift > 8 bpm, SmO2 still falling or RPE ≥ 18 → likely above (−0.3); 6–8 → repeat.
- **Zone updates:** verification card "존에 반영" (confirmed run raises a floor, failed run lowers a cap, from the run's own speed and last-5-min HR); multi-day lactate curve (≥ 3 speeds, Analysis tab "적용"); manual thresholds override. Any Free/LT1/LT2 session with speed + end lactate feeds the curve.
- LT2 **training** (not testing): LT2 session mode, 4×8 min (3-min easy) → 4×10 → 5×10 → recovery week → 3×15 → 2×20 → 30-min tempo, at MLSS speed, HR LT2 ±3; optional lactate after the last rep 3–4.5 = on target.
