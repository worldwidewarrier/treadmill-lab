## 2b. Service log / A/S 기록
**2026-10-05 · v1.1.11 (health check of the whole app, no feature work).** Every item has a regression test (unit: `test_exercise_end`, `test_engine`, `test_ble`, `test_alerts`, `test_verify`, `test_analysis`, `test_prescribe`; headless: `ui_strap`, `ui_data`, `ui_sw`).
- **Verification runs — where the run ended.** The recording runs on while the belt is stopped for the sample; "last 5 min" HR/α1, the 10→30-min HR drift, run time, SmO2 end slope and the end-sample rule were anchored to the end of the *recording*, so 1–3 min of recovery pulled HR down and SmO2 up and pushed the end-only MLSS proxy toward "at/below" (synthetic: a 100-s tail turned drift +8 into −0.5 and a falling SmO2 into "steady", so a run above MLSS was called "likely at/below" with a button raising LT2 from 10.5 to 10.8 km/h). Now anchored to `exerciseEnd` — estimated from heart rate, rules and limits in README §4 and in the code comment; shown in the card ("심박 하강으로 운동 종료 mm:ss 추정"), summary and CSV. Tuned and tested on synthetic recordings only (`node test/calib_exercise_end.mjs`: no false end on 544 runs without a tail; found in 92 % of 3,456 runs with one, 98.6 % of those within ±20 s). **Not yet checked against a real recording — re-open the 10/4 and 10/5 runs after updating, compare the estimated end with what happened, and re-read their last-5-min HR, drift and SmO2 line (the figures in §3 were produced before this fix).**
- **LT2 (interval) sessions.** The phase log decides: "last 5 min" = last 5 min of the last rep, end sample = first sample after it, a warm-up sample = baseline. With two or more reps no drift and no MLSS rule (recoveries clear lactate): the verdict rates the intensity only (3–4.5 after the last rep on target; < 3 low; 4.5–6 a little high; ≥ 6 or a rise > 1.0 across reps → slower), never changes zones, and the session is not a point of the multi-day curve. One 30-min rep (the MLSS check) is judged inside the rep exactly like a Free-mode run. Before, an interval session was judged by the cool-down (or, mid-fix, by warm-up → last rep "drift").
- **Lactate sample filing.** End = first sample after the estimated stop (also on a run given up at 12–16 min, also on an unfinished recording); a second sample in the same slot (two fingers) is ignored instead of becoming the "10-min" value. Card fields still override.
- **10→30-min drift**: a belt stop for the 10-min sample inside the 8–13-min window is left out of that window's mean (no longer reads as drift); paused stretches are excluded and "last 5 min" means 5 min of running. For a run without stops the figure is unchanged.
- **Pause** did not stop the stage / interval / target clocks (time left jumped on resume; finishing while paused lost that pause); paused minutes were inside the stage rows of a step test; "End stage" / Finish during a pause put the stage end at the press (HRVT of the last stage read from recovery). Fixed; an autosave taken during a pause counts the pause.
- **Strap silent** (out of range / reconnecting): the engine kept writing rows with the last heart rate and α1 and counted time in zone. Rows now carry no values (`gap: true`).
- **H10 reconnect**: a drop during a reconnect attempt started a second retry chain → every notification, i.e. every RR interval, was delivered twice for the rest of the session (α1 and RR export corrupted). A failed first connection kept reconnecting in the background and redrew the set-up screen every second. Fixed; pressing Connect again while an old attempt is still pending no longer cuts the new link (device ownership), and a cancelled connection is not reported as "connected".
- **Updates**: the new service worker filled its cache from the browser's HTTP cache (GitHub Pages: 10 min) — a release opened within ten minutes of the previous one kept the old files under the new version name (the reason for the force-update button). Precache now bypasses the HTTP cache. The start page falls back to the cached app when the host answers with an error or takes more than 4 s, and another page of the site can no longer overwrite the cached start page.
- **Screen stayed on after Finish**: Start requested the wake lock twice and only one was released. Fixed (quick on/off/on sequences end in the state asked for last).
- Smaller: lactate cues now fire on any tab; RR counter on the connect screen counted nothing before Start; α1 update interval from the Settings list was stored as text (time-in-zone became nonsense); speed / target band of the previous session leaked into the next; opening a deleted session hung; imported laps without speed gave HRVT "0 km/h"; demo sessions fed the multi-day curve and the LT1 auto-adjust; plan footnote said +10 % (it is +10 min); on a first run editing a setting rewrote the built-in defaults, so "Delete all data" kept the thresholds; Settings kept showing old values after a restore, and a restore during a session left the next session on the old settings; the detail view piled up chart objects on every edit; Home's last-session card showed "HR – · α1 –"; storage persistence is requested and shown in Settings.
- **Proposed, not done (ask the owner):** (1) a switch to turn α1 guidance off for this athlete (LT1-mode voice "알파1 낮음", the −3 bpm auto-adjust and the α1 sub-labels all assume α1 0.75 = LT1, which §3 says is wrong here); (2) store SmO2 at 1 Hz in sessions (Train.Red exports are 10 Hz → ~1 MB per session, and Home/Plan load every session); (3) "finish" an unfinished autosaved session; (4) artifact voice warning in test/free modes; (5) a field in the verification card to set the end of the run by hand when the estimate is off.

## 4. Solo protocol rules / 혼자 할 때 규칙
- Lactate technique: hands warm, washed with warm water and **fully dry (no alcohol residue, no sweat)**, wipe the first drop, no milking, fill the strip in one touch; end sample within 45 s of stopping; duplicate (two fingers) when a value looks odd (agree within 0.3). Keep caffeine/breakfast consistent on verification days. Strips: insert only when ready (2-min auto-off); meter ≥ 15 °C.
- **LT1 verification:** Free mode, speed entered, 35 min constant, cue "35". End ≤ 2.0 (and ≤ rest +1.0) → below; 2.1–2.5 → borderline; > 2.5 (or rise > 1.5) → above.
- **MLSS verification:** Free mode, **purpose = MLSS**, 30 min constant, warm-up outside the session, cue "30" (or "10,30" if a mid-run stop is possible: pause the app during the draw). Since v1.1.11 the time spent sampling before pressing 종료 no longer matters (end windows stop where heart rate shows the running stopped) — check the "심박 하강으로 운동 종료 mm:ss 추정" note in the card against what you did. With a 10-min sample: rise ≤ 1.0 → at/below (next +0.3), > 1.0 → above (−0.4). End-only proxy: < 25 min → withheld; end < 3 → below; ≥ 6 → above; 3–6 with HR drift (min 8–13 → last 5) ≤ 6 bpm and SmO2 steady → likely at/below (+0.3); drift > 8 bpm, SmO2 still falling or RPE ≥ 18 → likely above (−0.3); 6–8 → repeat.
- **Zone updates:** verification card "존에 반영" (confirmed run raises a floor, failed run lowers a cap, from the run's own speed and last-5-min HR); multi-day lactate curve (≥ 3 speeds, Analysis tab "적용"); manual thresholds override. Any Free/LT1/LT2 session with speed + end lactate feeds the curve.
- LT2 **training** (not testing): LT2 session mode, 4×8 min (3-min easy) → 4×10 → 5×10 → recovery week → 3×15 → 2×20 → 30-min tempo, at MLSS speed, HR LT2 ±3; optional lactate after the last rep 3–4.5 = on target (the card rates exactly this and leaves the zones alone).
